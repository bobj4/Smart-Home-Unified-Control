# Login times, remembered devices, verbose logging, room layout and fixes

One package covering seven changes, as requested. Every check passes
(lint, format, types, the full test suite including new browser tests,
bandit, migrations from an empty database, `alembic check`, pip-audit).

> **Security review needed before merging.** This changes login
> (`backend/app/routes/auth.py`), sessions (`backend/app/sessions.py`,
> protected) and adds a way to log in without the two-factor code on an
> approved device. Details are under "Security notes".

## 1. Settings pages no longer snap to the top

- **What was wrong:** after the earlier scroll fix, the Integrations page
  still jumped to the top for the owner. The server sent scripts with no
  caching instructions, so browsers kept running their old copy of
  `settings.js` for hours after an update. The fix was on disk, but the
  browser never loaded it.
- **Fix:** the page, scripts and styles are now served with
  `Cache-Control: no-cache`. The browser checks for a newer copy on each
  load (a quick 304 when unchanged), so updates take effect on the next
  reload.
- The live refresh now reads the scroll position just before swapping the
  page in. Before, it read it when loading began, so a scroll during a slow
  load was undone.
- Files: `backend/main.py`, `web/js/settings.js`.
- Test: `test_settings_no_jump.py::test_scripts_are_revalidated_so_updates_load`.

## 2. Remember this device (two-factor)

- **Login page:** new checkbox, "Remember this device (no code needed here
  next time)". After a successful login with a code, the browser is
  approved. Later logins on that browser need only the password. When the
  browser holds an approved device, the login page says "This device is
  remembered: leave the code empty."
- **What it needs:** the password is still required, and failed attempts
  still count towards the login rate limit. Each approval belongs to one
  user, so someone else logging in on the same browser still needs their
  own code. Other browsers always need the code.
- **Where approvals end:**
  - when the user removes it (My account > Approved devices)
  - when an admin removes it (Admin > Approved devices)
  - when the time set in Login times runs out (default: never)
  - on a password change, including an admin setting a member's password
    or a recovery-code reset
  - when the user replaces or turns off their authenticator
  - when the account is turned inactive or removed from its last home
- **My account:** devices now has two tabs, "Logged-in devices" (as
  before) and "Approved devices". Each approved device shows its name
  (for example "Chrome on Windows", worked out from the browser, never the
  raw header), the IP it was approved from, when it was approved and last
  used, and when it expires. "(this device)" marks the current one.
- **Admin:** an "Approved devices" list with every approved device of
  everyone who shares a home where you are an admin, and whose each one is.
  Each has a Remove button. People in other homes are never shown.
- **How it works:** a random 32-byte token sits in an HttpOnly, Secure,
  SameSite=Strict cookie (`trusted_device`, path `/api/v1`). The database
  keeps only its SHA-256 (table `trusted_devices`). Expiry is worked out
  from the approval date and the current Login times setting, so changing
  the setting also applies to devices approved before.
- Audit events: `device_remembered`, `device_forgotten`, and
  `login_success` with `method: trusted_device`.
- Files: `backend/app/login_times.py` (new), `backend/app/routes/login_times.py`
  (new), `backend/app/routes/auth.py`, `backend/app/routes/account.py`,
  `backend/app/routes/admin.py`, `backend/app/routes/members.py`,
  `backend/app/routes/member_access.py`, `web/js/trusted-devices.js` (new),
  `web/js/account.js`, `web/js/app.js`, `web/js/api.js`, `web/public/index.html`.

## 3. Admin: Login times

- New "Login times" panel in Settings > Admin, for every account (like the
  other login rules):

  | Setting | Default | Range |
  | --- | --- | --- |
  | Keep me logged in | 30 days | 1–365 |
  | Remember me (login name filled in) | 365 days | 1–3650 |
  | Remember this device (skip the code) | 0 = forever | 0–3650 |

- The login page's checkbox shows the current keep time ("Keep me logged
  in for 14 days").
- API: `GET/PUT /api/v1/admin/login-times`, admins only. Values are
  strict integers, checked against the ranges. Changes are audited as
  `login_times_changed`, with the before and after values.
- `KEEP_LOGGED_IN_SECONDS` (environment) is removed; the database setting
  replaces it. `create_session()` now takes the kept lifetime from its
  caller (`keep_seconds`).
- New logins use the new keep-logged-in and remember-me times. Sessions
  and cookies already issued keep theirs.
- Files: `backend/app/models.py` (`SystemSettings` columns),
  `backend/app/sessions.py`, `backend/app/db_config.py`, `web/js/login-times.js` (new),
  `web/js/admin.js`.

## 4. Verbose logging (Activity log)

- New "Verbose logging" switch at the top of Settings > Activity log. It is
  off by default, admins only, and applies to the whole installation.
  Switching it is audited as `logging_verbose_on` / `logging_verbose_off`.
- While it is on, these events are added (all named `verbose_…`; the
  activity log shows their details on a second line):

  | Event | Recorded | Details |
  | --- | --- | --- |
  | `verbose_request` | every change request (POST/PUT/PATCH/DELETE under `/api/`); page reads are not recorded | who, method, path, status, ms |
  | `verbose_vendor_command` | each command sent to Cync, Rheem or Samsung | integration, device, command, ok/failed, status, reason, ms |
  | `verbose_refresh` | each background read that actually ran (TVs only when one changed), and every failure | integration, result, reason, ms |
  | `verbose_device_offline` / `verbose_device_online` | any device's connection changing, from any source | device, integration |

- **Never recorded:** request bodies, query strings, headers or cookies.
  Details still go through the audit log's secret redaction.
- The adapters under `integrations/` are protected, so vendor detail is
  recorded where the app calls them: commands in `device_io.py`, background
  reads in `refresh.py`. Online/offline changes come from a SQLAlchemy
  hook, so they are caught wherever they happen.
- Vendor commands are logged in a separate database session, so logging
  never commits or rolls back the request's own changes.
- Files: `backend/app/verbose.py` (new), `backend/app/routes/verbose.py` (new),
  `backend/app/refresh.py`, `backend/app/device_io.py`, `backend/main.py`,
  `backend/app/models.py` (`Device.online` loads its old value when changed),
  `web/js/activity-log.js`, `web/css/app.css`.
- Note: with the switch on, rows add up quickly. Turn it off when done.

## 5. Thermostat tile order

## 6. Disconnected devices are drawn off

- While a device is offline, its tile shows the off state: the power
  toggle is off, lights have no glow, and thermostats and water heaters
  show status Off. It stays dimmed as before.
- When it comes back online, the next refresh shows its real state again.
- Only the drawing changes; the stored state is left alone.
- File: `web/js/devices.js`.

## 7. Room layout editor, with a Thermostats room

- The Devices page shows thermostats in their own room, "Thermostats",
  at the top by default.
- An "Edit layout" button opens a window that moves rooms up and down,
  with Save, Reset (back to Thermostats first) and Cancel.
- The order is saved for each user and home, and never changes anyone
  else's page. Rooms missing from a user's order (new rooms) follow in
  name order, with "No room" last.
- API: `GET/PUT /api/v1/homes/{home_id}/layout`, for any member of the
  home. At most 200 entries of up to 50 characters; repeats are dropped.
  Audited as `room_layout_changed`.
- Files: `backend/app/routes/layout.py` (new), `backend/app/models.py`
  (`RoomLayout`), `web/js/room-layout.js` (new), `web/js/devices.js`, `web/css/app.css`.

## Security notes (for the reviewer)

- **Protected file:** `backend/app/sessions.py`. The only change is that
  the kept-session lifetime comes from the caller (`keep_seconds`) instead
  of an environment value. The idle-timeout rule is unchanged.
- **Remembered devices** replace only the second factor, never the
  password. Tokens are 256-bit, stored hashed, compared by hash lookup,
  and tied to one user. They end on every credential change listed above.
  Admins can see and remove them only for people in their own homes.
- **Cookies:** `trusted_device` is HttpOnly, Secure and SameSite=Strict
  with path `/api/v1`, so My account can mark "this device".
  `remembered_login` keeps path `/api/v1/auth`.
- **`GET /api/v1/auth/remembered`** (public) now also returns whether this
  browser holds a device cookie (not whose, and not whether it is valid)
  and the keep-logged-in days.
- **Verbose logging** records no secrets and is off by default.
- **Serving:** the web files are revalidated on each load. Nothing else
  about serving changes, and the security headers still apply.
